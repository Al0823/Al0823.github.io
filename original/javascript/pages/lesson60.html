Operator Precedence



Operator Precedence chooses the order in which operators are evaluated in expressions.

Operators with higher precedence are executed before operators with lower precedence.

Understanding precedence helps you write correct expressions and avoid unexpected results.


Precedence Rules


Operators in JavaScript are ranked from highest precedence to lowest.

For example, multiplication (*) has higher precedence than addition (+), so it is executed first.

Parentheses () can be used to override precedence and force certain calculations to happen first.

Explanation:

Multiplication (*) has higher precedence than addition (+), so 4 * 2 is evaluated first, giving 8.
Then 3 + 8 = 11.


Using Parentheses to Change Precedence


Parentheses () have the highest precedence. They can be used to group parts of an expression and ensure they are evaluated first.

Operator Associativity


When operators have the same precedence, associativity determines the order of evaluation.

Most operators have left-to-right associativity, which means they are evaluated from left to right.

Some operators, like the assignment operator =, have right-to-left associativity.


Example: Left-to-Right Associativity




Explanation:

Subtraction (-) has left-to-right associativity.
First 10 - 5 = 5, then 5 - 2 = 3.


Example: Right-to-Left Associativity




Explanation:

Assignment (=) has right-to-left associativity.
First c = 5, then b = c (5), then a = b (5).


Common Precedence Gotchas


1. Unary operators (like ++, --, !) have higher precedence than arithmetic operators.

2. Comparison operators (<, >, ==) have lower precedence than arithmetic operators.

3. Always use parentheses if you want to ensure a specific order of evaluation.

Summary


- Operator precedence determines which parts of an expression are evaluated first.
- Parentheses () can override precedence.
- Operators with the same precedence follow associativity rules (left-to-right or right-to-left).
- Understanding precedence helps prevent bugs and ensures your code behaves as expected.
